# Course Reflection

The most difficult concept in the course was understanding how to design a scalable system while maintaining data consistency. I initially found it challenging to understand how components such as caches, databases, queues, and background workers interact, especially when several users perform operations simultaneously. I overcame this by breaking the system into individual components, tracing requests step by step, and calculating expected traffic before deciding where each component should be used. Working through the ticketing example also helped me understand why database transactions, constraints, and atomic updates are essential for preventing two customers from buying the same seat.

Based on the feedback I received on my capstone, I would improve the architecture documentation and diagrams. The feedback highlighted the importance of showing the complete flow between components instead of simply listing them. I would make the request paths clearer, explain how asynchronous jobs are processed without blocking user requests, and document failure handling, retries, and trade-offs more explicitly. This would make the design easier for another developer to understand and implement.

Next, I plan to learn more about database concurrency, transaction isolation, and distributed systems. I also want to practise load testing with tools such as k6 and monitoring performance with Grafana. These skills will help me evaluate whether an architecture can handle its expected workload and identify bottlenecks before deployment. My goal is to become better at designing systems that are not only functional but also reliable, secure, and scalable under real-world conditions.
